Phase 3 · 완료

쿠폰을 넣으면 금액이 깎인다

장바구니에서 쿠폰 코드를 넣으면 할인 금액과 결제 예정 금액이 바로 바뀝니다. 조건을 못 채우면 이유를 알려 주고 적용하지 않습니다.

한 줄 요약: 5,000원 할인 쿠폰을 만들고, "3만 원 이상일 때만 사용 가능"이라는 조건과 "한 번 쓰면 끝"이라는 규칙을 서버가 판단하게 했습니다.

안전장치

결제 금액이 음수가 되는 일은 없습니다.

중요

금액을 미리 계산해 보는 것만으로는 쿠폰이 소모되지 않는다

화면에서 쿠폰을 넣어 보는 것은 "얼마가 될지 물어보기"일 뿐입니다. 쿠폰이 실제로 사용 처리되는 시점은 주문이 생성되는 순간뿐입니다. (Phase 4)

QA 관점

경계값: 딱 30,000원이면 되는가

"30,000원 이상"이라는 문장은 30,000원을 포함합니다. 그런데 프로그램에서는 이 한 글자 차이로 버그가 자주 납니다. 그래서 금액을 다음 세 지점에서 확인했습니다.

상품 금액기대 결과확인 방법
29,999원쿠폰 사용 불가부품 검사(계산 함수만 떼어서)
30,000원 (머그컵 3개)쿠폰 사용 가능부품 검사 + 서버 요청 + 브라우저 클릭
30,001원쿠폰 사용 가능부품 검사

초기 상품에 10,000원짜리 머그컵을 넣어 둔 이유가 여기 있습니다. 3개면 정확히 30,000원이 되어 경계값을 실제 화면에서도 확인할 수 있습니다. 테스트하기 좋은 데이터를 미리 설계해 두는 것도 QA의 일입니다.

확인 과정에서 나온 2건

앱 버그 · 브라우저 확인에서 발견

쿠폰이 왜 빠졌는지 손님이 알 수 없었다

쿠폰을 적용한 뒤 수량을 줄여 30,000원 아래로 내려가면, 쿠폰이 자동으로 해제되면서 이유가 잠깐 표시됐다가 곧바로 "수량을 변경했습니다"라는 성공 메시지에 덮였습니다. 손님 입장에서는 할인이 소리 없이 사라진 것처럼 보입니다.

고친 방법: 알려야 할 이유가 있으면 성공 메시지보다 먼저 보이도록 순서를 정리했습니다. 화면 값(결제 금액)만 봤다면 통과했을 문제이고, 손님이 이해할 수 있는가를 함께 봤기 때문에 잡혔습니다.

검사 스크립트 문제 · 자동화 관점

페이지 새로고침이 겹쳐 검사가 깨졌다

손님을 바꾸면 화면이 스스로 새로고침되는데, 그 사이에 검사 스크립트가 또 새로고침을 걸어 충돌했습니다. 앱의 버그는 아니지만, 이런 타이밍 문제가 가끔 실패하는 불안정한 검사의 대표적인 원인입니다.

고친 방법: "몇 초 기다리기" 대신 "손님 선택이 실제로 바뀔 때까지 기다리기"라는 분명한 조건을 넣었습니다. Phase 6에서 같은 원칙을 그대로 씁니다.

다음 단계는 Phase 4 · 주문과 취소입니다. 주문하면 재고가 줄고, 취소하면 재고와 쿠폰이 돌아옵니다. 전체 진행 상황은 진행 현황에서 볼 수 있습니다.
